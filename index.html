Stop 01

The “final-final-v3” problem

Without version control

project-final/
project-final-new/
project-really-final/
project-really-final-v3/

Which folder is current? Which change fixed the bug — and who made it?

With version control

  • Named checkpoints with messages
  • Exact differences between versions
  • Parallel lines of work
  • A history you can explain

Git is not a magic backup. If the only copy lives on your laptop and the laptop is lost, so is the history. A remote copy is a separate decision.

Stop 02

Git is not GitHub — and neither is Copilot

Tool

Git

Version-control software on your computer. Records history locally and works offline.

Platform

GitHub

Hosts repositories and adds issues, pull requests, reviews and automation for collaboration.

Assistant

GitHub Copilot

AI help inside the workflow. Its suggestions and actions still need your review.

Saving in the editor, committing in Git, pushing to GitHub and deploying a website are four different steps.

Stop 03

Save ≠ stage ≠ commit

Working filesEdit and save in your editor.
git add →
Staging areaChoose the exact change to record.
git commit →
Commit historyA checkpoint with a message.

git diff compares working files ↔ staging.

git diff --staged compares staging ↔ last commit.

After git add, plain git diff can look empty. Your change did not disappear — it moved to staging.

Stop 04 · Try it

Your first two checkpoints

Use the git-basics folder. It contains one file, notes.md. Run these commands inside that folder — never inside an important project.

1Start tracking

git init -b main
git status
git add notes.md
git diff --staged
git commit -m "Add learning goals"

If Git asks who you are, set your name and email once with git config --global user.name and user.email.

2Make and inspect a change

Add a new line to notes.md in your editor, for example - Build one small project., and save.

git diff
git add notes.md
git diff --staged
git commit -m "Add a practice goal"

Predict what the diff will show before you run it. A plus sign marks an added line.

3Read the story

git log --oneline -3
git show HEAD:notes.md
git status

Example output — your commit IDs will differ

7172ba7 Add a practice goal
3fcbeec Add learning goals

Stop 05

From a branch to a reviewed change

  1. IssueDescribe the problem and what “done” means.
  2. Branch + commitsMake small, understandable changes. git switch -c improve-notes
  3. Pull requestPropose the change. Reviewers read the diff and check the evidence.
  4. MergeIntegrate reviewed work. Opening a PR never obliges anyone to merge it.
Remote commands in one line each
  • git clone <url> — make a local copy of a remote repository.
  • git fetch — download updates without changing your branch.
  • git pull — fetch and integrate updates (merge or rebase, depending on configuration).
  • git push — send your commits to a remote you have permission to write to.

Stop 06

Share code, not secrets

Before adding

Read git status. Stage only the files you intend to share.

Before publishing

Check for API keys, passwords, personal data, licences and repository visibility.

If a secret leaks

Revoke or rotate it. Deleting the line in a later commit does not remove it from history.

Meet your AI teammate

The current Dev Days round focuses on the GitHub Copilot app and Copilot CLI. The workflow matters more than the tool you start with.

  1. PlanGive context, constraints and a clear task.
  2. BuildInspect proposed edits and tool actions.
  3. ReviewRead the diff and the real test results.
  4. ShipMerge or publish only with deliberate approval.
Vague

“Fix everything and make it better.”

Bounded

“Explain the bug first. Change only the relevant function. Keep the interface. Run the named tests and show the actual result.”

Stop 08 · Copilot demo 1

Explain, test, fix: why is 4 “prime”?

Open copilot-demo. prime.py contains an intentional bug, and test_prime.py catches it.

Recorded by running the starter and the reference fix with Python 3.10.

2 · Ask Copilot — explanation first

Prompt

Explain this Python function in simple terms. Do not edit yet. Why does is_prime(4) return True? Suggest a minimal fix and tests covering negative numbers, 0, 1, primes and perfect squares. After I approve the edit, run the tests and show the actual output. If you cannot run them, say so.

3 · Approve a small change, then re-run the tests

  • Does the explanation mention that range() excludes its end?
  • Did it change only is_prime?
  • Did the tests actually run — or did it just say they “should pass”?
Stuck? See a reference fix (hand-written, not Copilot output) 
from math import isqrt

def is_prime(n):
    if n < 2:
        return False
    for divisor in range(2, isqrt(n) + 1):
        if n % divisor == 0:
            return False
    return True

Stop 09 · Copilot demo 2

One scoped improvement: add a filter

Open copilot-demo/index.html — a small learning-goals list. Ask Copilot to add a case-insensitive filter without breaking anything that already works.

Prompt

In the existing index.html, add a labelled case-insensitive text filter for the learning-goals list. Preserve adding a goal, ignore blank submissions, keep keyboard access, and show a clear no-results message. Treat user input as text, not HTML. Do not install dependencies, add network calls or change unrelated files. First explain your plan; then implement the scoped change. Show the diff and a manual test checklist. Only claim checks passed if you actually ran them.

Acceptance checks

  • “git” shows matching goals
  • “GIT” shows the same matches
  • “zzzz” shows a no-results message
  • Clearing the filter shows every goal
  • Adding a matching goal while filtering keeps it visible
